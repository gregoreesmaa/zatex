# zatex-png

KaTeX-compatible LaTeX → PNG screenshots for the zatex monorepo.
One backend per OS behind a small `Backend` interface; the layout core
stays portable. Strict hierarchy: `zatex-png` depends on `zatex`,
never the reverse, and no layout math lives in this package — it only
scales the core's integer font units to pixels and draws.

## Usage

```
zatex-png [--display] [--px N] [--font PATH] "<tex>" out.png
zatex-png --corpus PATH --outdir DIR [--px N] [--font PATH]
```

Defaults: 48 px per em, `../zatex/fixtures/fonts/latinmodern-math.otf` (the
pinned fixture, so same input renders identical pixels). Batch mode
renders every `accept` row of the corpus to `<id>.png`, skips rejects,
and exits nonzero if any accept row fails to lay out.

`-Dbackend=auto|cg|software` (a `zig build` option, default `auto`)
overrides backend selection: `auto` picks CoreGraphics on Apple OSes
and the software rasterizer elsewhere; `software` forces the portable
backend anywhere (how Linux/Windows/Android renders are verified from
a macOS host, and how the Linux oracle image builds).

## Layout

- `src/main.zig` — CLI (single formula or corpus batch).
- `src/render.zig` — IR → pixels (portable coordinate mapping over a
  `Backend` canvas; no layout math, ever).
- `src/font.zig` — font loading: portable `otmath` metrics plus the
  backend font handle for drawing.
- `src/backend.zig` — OS selection + the `Backend` interface
  (`Font`/`Canvas`/`Run`); a new OS adds one file, never touches the
  callers.
- `src/cg_backend.zig` — CoreGraphics implementation (reference).
  `src/ios_backend.zig` — iOS re-export of it.
- `src/sw_backend.zig` — portable software rasterizer (the endgame:
  CFF/Type2 outlines from `sw_font.zig`, scanline fill from
  `sw_raster.zig`, PNG via `std.compress.flate` from `sw_png.zig`;
  zero host dependencies beyond libc). `src/linux_backend.zig`,
  `src/windows_backend.zig`, `src/android_backend.zig` re-export it
  with per-OS link notes, ready to host native backends later.
- `src/cg.zig` — manual CoreGraphics/CoreText/ImageIO bindings.
- `screenshots/` — visual regression set: curated corpus, checked-in
  baseline PNGs, and `render.sh`. See `screenshots/README.md`.

## Backends

| OS | File | Status |
| --- | --- | --- |
| macOS | `cg_backend.zig` | Reference implementation. CI re-renders + `compare_shots.py`-compares. |
| iOS | `ios_backend.zig` | Wired (CoreGraphics exists on iOS); compile check needs the Xcode iOS SDK — SDK CI runner. |
| Linux | `linux_backend.zig` → software core | Verified: builds, renders the full corpus, dimensions bit-equal to CoreGraphics (154/154). |
| Windows | `windows_backend.zig` → software core | Verified: `zig build -Dtarget=x86_64-windows` links. A DirectWrite backend can land in this file later (see its header for the extents re-check rule). |
| Android | `android_backend.zig` → software core | File compiles; full `aarch64-linux-android` link needs NDK libc (Zig 0.16 ships no Android libc) — NDK CI runner. |

Canvas convention (all backends): caller floats in pixels, origin
bottom-left, y-up; the core-to-canvas flip lives in portable
`render.zig`, never in backends.

## Software-backend pixel fidelity (read before comparing)

Layout-affecting metrics are exact: outline ink boxes match CoreText
on all 4802 fixture glyphs (`zig build test` asserts this;
worst disagreement 0), so re-renders are dimension-identical to the
CoreGraphics backend, and rule rects are pixel-identical. Glyph
*interiors* agree; glyph *edges* differ systematically: CoreText fonts
are hinted, smoothed, and dropout-controlled, while the software
rasterizer paints geometric coverage. Expect ~5% of pixels beyond
`compare_shots.py`'s same-rasterizer deltas at edges — that is
cross-rasterizer spread, not a layout bug, and the pixel gate stays
CoreGraphics-scoped for exactly this reason. (Matching CoreText's
hinting would mean reimplementing proprietary grid-fitting; the
geometry both rasterizers share is already proven identical above.)

## Verification boundary (this machine: macOS/arm64, no Xcode iOS SDK)

- `zig build test` and `zig build -Dbackend=software test`: green.
- `zig build -Dtarget=x86_64-linux|aarch64-linux|x86_64-windows`: link OK.
- `zig build-obj` on `android_backend.zig` / `ios_backend.zig`: compile OK.
- `zig build -Dtarget=aarch64-linux-android`: needs NDK libc (fails in
  libc provisioning, before our code matters) — NDK runner.
- `zig build -Dtarget=aarch64-ios`: compiles our code, fails only on
  missing Apple frameworks (no SDK paths) — Xcode runner.
